Most requests should never reach the model.

A provider-agnostic GenAI gateway. Policy checks, structured retrieval and a cache run first. A model call happens only when nothing else resolves the request, and every path is rate limited, traced and audited without storing the prompt.

The mock model is deterministic and has no real quality. It exists so the pipeline around it can be exercised without a paid API. Metrics are not exposed on this page.

The model is the last resort

Most requests do not need one. Cheap, deterministic checks run first, so the model only sees what is left.

1

Block before spend

A rate limit per client, then policy rules for secret exfiltration and prompt injection. A blocked prompt is never cached and never reaches a model.

2

Answer without a model

A strong runbook match answers directly. A weak match attaches context. A cache hit returns an earlier answer for the same prompt and context.

3

Check what comes back

Responses are validated for length and leaked-prompt markers, and hedging answers are flagged for human review. Every path writes an audit record.

Audit without storing the prompt

The audit log keeps a short hash and the length of the prompt and the response, never the text. The request panel above shows the exact record the gateway wrote for your last request.

Run it locally

Python 3.12. No API key needed, the default provider is the mock.

python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .

uvicorn genai_gateway.app:app --port 8000
scripts/smoke_test.sh http://localhost:8000
docker compose up -d redis   # optional shared cache
python -m pytest tests/ -v

An Anthropic provider exists in the repo. The default path never calls it.

What this does not do
  • It is an independently built portfolio project. The author has no production experience running a GenAI gateway at scale, and the README says so.
  • Policy rules are regular expressions. They stop the obvious attacks, not a determined one.
  • The rate limiter is in memory, so it is correct for one instance. Several instances need Redis behind it.
  • The runbook knowledge base has three entries. It shows the pattern, it is not a retrieval system.
